## Merge Strategy Revision
```text
Merge commit
= preserve individual commits
+ explicit merge point

Squash and merge
= many PR commits → one commit

Rebase and merge
= preserve individual commits
+ linear history
- no explicit merge commit
```

Fast rule:
```text
One commit → Squash
Linear history → Rebase
Merge point → Merge commit
```

## Confusing Pairs Reviewed

### Fetch vs Pull
```text
fetch = download remote info, no auto-integration
pull = fetch + integrate
```

### Fork vs Template
```text
fork = related copy, often contribution
template = new independent repo from starter structure
```

### Issue vs Discussion
```text
Issue = actionable tracked work
Discussion = ideas/Q&A/broader conversation
```

### Assignee vs Reviewer
```text
Assignee = responsible for work
Reviewer = evaluates proposed changes
```

### CODEOWNERS vs Branch Rules
```text
CODEOWNERS = who reviews
Branch rules = what must pass
```

### Tag vs Release
```text
Tag = exact point/version
Release = published version + notes/assets
```

### Star vs Watch vs Follow
```text
Star = bookmark repo
Watch = repo notifications
Follow = user/org activity
```

### github.dev vs Codespaces
```text
github.dev = quick browser editor
Codespaces = full cloud dev environment
```

### Iteration vs Milestone
```text
Iteration = sprint/time-box
Milestone = goal/release
```

### Authentication vs Authorization
```text
Authentication = who are you?
Authorization = what may you do?
```

### Secret scanning vs Push protection
```text
Secret scanning = detect exposed secret
Push protection = stop/warn during push
```
