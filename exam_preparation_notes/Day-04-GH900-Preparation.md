## GitHub Projects
Flexible planning/tracking workspace containing:
- Issues
- Pull Requests
- Draft issues
- custom fields
- status
- dates
- iterations
- views

### Repository vs Project
```text
Repository = code + commits + branches + PRs + issues
Project = planning/tracking workspace
```

### Core layouts
**Table**
- spreadsheet-like
- best for structured fields

**Board**
- Kanban-like
- best for workflow/status

**Roadmap**
- timeline
- best for dates / longer-term planning

Shortcut:
```text
Board = WHERE is work in workflow?
Roadmap = WHEN is work happening?
Table = WHAT structured details do I need?
```

### Custom fields
Examples:
```text
Priority
Effort
Risk
Team
Sprint
Target date
Story points
```

### Labels vs Custom Fields
- Labels = lightweight categorization.
- Custom fields = structured planning metadata.

### Status field
Examples:
```text
Backlog
Ready
In Progress
Review
Blocked
Done
```

### Iterations
Recurring time boxes:
```text
Sprint 1
Sprint 2
Sprint 3
```

### Milestone vs Iteration
```text
Milestone = goal/release
Iteration = recurring time-box
```

### Filtering / Sorting / Grouping
- Filter = which items appear.
- Sort = order of items.
- Group = divide into sections.

### Multiple views
Same underlying work can be represented differently:
```text
Team Board
Release Roadmap
QA Table
High Priority Bugs
```

### Draft issues
Planning placeholders that may later become full Issues.

### Project templates
Reusable planning structure including fields/views/workflows.

### Project automation
Automate project maintenance, e.g.:
```text
Item added → Status=Todo
PR merged → Status=Done
```
